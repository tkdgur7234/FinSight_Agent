## 📌 기능 개요

### 1. 각종 지표 · 경제 뉴스 기반 데일리 시황 리포트

#### 1-1. Index (25-12-08)
S&P 500, Nasdaq, Russell, Bitcoin 등 주요 지수의 일간 변동값 제공
- 주요 지수 일간 변동값 수집

#### 1-2. S&P 500 Map (25-12-08)
S&P 500 구성 종목의 일간 흐름을 한눈에 파악할 수 있는 맵 시각화
- apiflash 사이트를 활용해 "S&P 500 Map" 캡쳐 후 불러오기

#### 1-3. Released Main Economy Indicators (25-12-21)
전일 발표된 주요 경제 지표를 자동 수집해 시황에 반영
- 대상 지표: CPI, PPI, PCE, NFP, 신규 실업수당 청구, 소매판매, FOMC  
- FRED API 및 Forex Factory 크롤링을 통해 데이터 수집·포스팅

#### 1-4. Most Impact Market News (25-12-31)
전날 시장에 가장 큰 영향을 준 주요 뉴스 수집 및 제시
- Google News RSS 기반 크롤링  
- 현상 → 원인 → 주도주 3단계 전략으로 뉴스 분류  
- URL 기준 중복 제거, RSS의 title + description만 LLM에 전달해 토큰 절약  
- LLM을 활용해 시장에 가장 큰 영향을 준 핵심 재료 요약 제공

### 2. 관심 종목 집중 모니터링

#### 2-1. 관심 종목 커뮤니티 감성 분석 (25-01-08)
커뮤니티 반응을 기반으로 종목별 투자 심리(공포·탐욕) 분석
- Reddit(미국 주식), 네이버 종토방(한국 주식)에서 종목별 게시물 50~100개 크롤링  
- JSON DB 기반 평균 글 리젠 속도를 활용한 악재/호재 분석  
- 1차 필터링: 인기순 정렬, 글자 수 및 키워드 필터  
- 2차 필터링: 의미 있는 핵심 의견 10개로 요약  
- 요약된 의견을 바탕으로 공포·탐욕 지수 산정 및 원인 분석

#### 2-2. 관심 종목 뉴스 (25-01-09)
관심 종목과 직접적으로 관련된 핵심 뉴스만 선별 제공
- RSS에서 5개 기사 수집 후 difflib 기반 유사도 50% 이상 기사 제거  
- 중복 제거 후 상위 2개 기사만 선택  
- 한국 시간 기준 어제 09:00 ~ 오늘 09:00 시간 필터 적용  
- 유료 뉴스 필터링

### 3. 이상 거래 감지

#### 3-1. 대규모 거래 감지 (26-01-26)
통계적 이상치를 기반으로 비정상적인 대규모 거래 포착
- S&P 500, Nasdaq, NYSE 대상  
- Finviz 기준 Rel Volume > 1.5인 상위 60개 종목 크롤링  
- yfinance로 작년~현재 일봉 데이터를 가져와 Z-score 계산  
- Z-score > 2 종목을 대규모 거래로 판단  
- 주간·월간 대규모 거래 빈도수 + Z-score 리포팅

#### 3-2. 주요 종목 내부자 거래 감시 (26-02-08)
임원 및 내부자의 미공개 정보 기반 거래 패턴 분석
- OpenInsider 최신순 5,000건 수집 후 최근 1개월 데이터만 유지  
- 1차 필터링: 동전주($3 미만) 제거, 매수 $20k 이상·매도 $400k 이상  
- 2차 필터링: 시총 3,500억 이상, 일 거래대금 30억 이상  
- 리포팅 분류  
  - 집단 매수: 최근 30일 내 3명 이상 매수  
  - 주요 매수: $100k 이상 + C-Level  
  - 대량 매도: $300k 이상

# 시스템 구조 및 수정 기록

----------------------------------------------
수정 (25-12-21)  
기존에는 n8n으로 모두 작업.  
         ↓  
시스템의 유연성과 확장성을 위해,  
데이터 분석 및 리포트 렌더링 로직은 서버를 구축해(FastAPI) 마이크로서비스화 하였으며,  
워크플로우 제어는 n8n을 사용하여 로직과 오케스트레이션을 분리.

Finshigt_agent/  
├── backend/               # Python 서버 (FastAPI)  
│   ├── main.py            # 메인 서버 코드  
│   ├── routers/           # 포스팅할 엔드포인트 모음  
│   ├── services/          # 각종 기능 구현 코드  
│   ├── templates/         # 웹 시각화 html  
│   ├── requirements.txt   # 라이브러리 목록  
│   └── .venv/             # 가상 환경  
└── n8n/                   # n8n 관련 파일 (Docker 등)

(25-12-22)  
1. n8n 설치 위치와 클론된 폴더 위치가 맞아야함.  
2. 가상환경 생성 및 접속  
python -m venv venv  
source venv/bin/activate  
3. 라이브러리 내려받기  
pip install -r requirements.txt  
4. ".env" 환경변수 파일 생성  
api 키 입력  
5. 서버 실행  
> uvicorn main:app --reload  
> (-> http://127.0.0.1:8000)  
> or  
> uvicorn main:app --reload --host 0.0.0.0  
> (-> http://0.0.0.0:8000)

## 25-01-22

### (1) 3-1. 대규모 거래 감지 로직으로 수정

- Finviz 크롤링  

> 사용 이유 : Finviz가 대규모 거래 체결 감지하는 방식이  
> 자체적으로 종목의 상대 거래량  
> (RVOL = 현재_거래량 / 3개월_평균_거래량)을 계산해서 사용하기 때문.

- SQLite를 통해 날짜, 종목, 당일 총 거래량, 거래 대금, RVOL, Z-score 저장  

- 이벤트 판단  
  - 1차 : Finviz Rel_volume > 1.5  
  - 2차 : Z-score로 단순 거래량 증가인지 고래 출몰인지 판단  

- 주간/월간(고래 출몰) 빈도수 + Z-score 리포팅

> Rel Volume이 있는데 굳이 Z-score까지 사용하는 이유?  
> - 변동성이 심한 중소형주는 대형주와 달리  
>   단순 RVOL만 사용하면 오판 가능성 존재
